# Phase 1 確認手順

## この段階の目的

最小限のYouTubeプレイヤーを動かし、埋め込みブラウザでのログインと音声キャプチャの可否を確認します。
この版はVSTホスト、Audio Engine、Discord送信、メタデータ収集を実装していません。

## 開発側の確認（2026-09-15 / Windows 11 build 26200）

| 項目 | 結果 |
|---|---|
| .NET 10 Releaseビルド | 成功、警告0・エラー0 |
| URL入力・PCM単体検証 | 15項目成功 |
| 自己完結型win-x64発行 | 成功 |
| WPFとYouTubeトップページの実表示 | 確認済み |
| ローカルテスト音からのPCM | 44,100 Hz / 2ch、peak 0.030000、非ゼロ受信数増加 |
| YouTube動画の描画とPCM | Big Buck Bunny（aqz-KE-bpKQ）で映像進行・非ゼロ受信数増加、peak約0.13を確認 |
| 通常→診断→通常の切り替え | 画面とブラウザの再生成を確認 |
| 専用プロファイル | アプリ専用パスで作成を確認。Cookieの中身は検査していない |
| Googleログイン・再起動後のログイン維持 | ユーザー確認待ち |
| スピーカーでの元音抑止・通常音声 | 聴感確認待ち |

テスト音とYouTube動画のカウンターは同一診断セッションでは累積です。新しい動画の検証では、数値が引き続き増加することと現在のpeakを確認してください。
この表は万能なYouTube互換性や低遅延を保証するものではありません。

画面確認の途中でユーザーのEsc操作によりComputer Useが停止されたため、それ以降は画面操作を実施していません。
終了処理の待機とエラー表示を調整した最終版は `artifacts/phase1-release/` に発行し、再ビルドと15項目の検証は成功しています。最終版での再起動・ログイン確認は未実施です。
画面に以前の版が残っている場合は通常終了してから、`Start-Mizu.cmd` で最終版を起動してください。

## 1. 通常再生

1. `Start-Mizu.cmd` または発行フォルダーの `Mizu.YT.Player.exe` を起動します。
2. 「PCM取得のみ」がOFFであることを確認します。
3. YouTube内で検索し、動画を再生してください。
4. 一時停止、再開、シーク、音量、関連動画、プレイリスト、戻る・進むを確認します。
5. 音が二重にならず聞こえるか確認します。

## 2. ログインの成立と維持

1. YouTube標準のログインボタンから、ユーザー自身でログインします。
2. アプリを通常終了し、再起動します。
3. ログインが維持されるか、アカウントのメニュー等で確認します。
4. 拒否された場合は表示されたエラー文を報告してください。パスワード、Cookie、認証コードは送らないでください。

Googleの判定を回避するコードは含みません。外部ブラウザでのOAuth成功をこの確認の代わりにはしません。

## 3. 音声経路

1. スピーカー／ヘッドフォンの音量を小さくし、通常モードで「診断用テスト音を開く」→「テスト音を開始」。
2. 小さな440 Hz音が聞こえることを確認し、停止します。
3. 「PCM取得のみ」をONにします。ページは読み直されます。
4. 必要ならテスト音ページを再度開き、「テスト音を開始」。
5. `non-zero` が増え、`peak` が約0.03を表示し、それでもスピーカーが無音か確認します。
6. YouTube動画でも同じ確認をします。ページ読み込み後は再生を押してください。
7. 動画の一時停止・シーク・遷移後に受信が適切に止まり／再開するか確認します。
8. 診断をOFFへ戻して再生すると、通常音声へ戻るか確認します。

**判定:** ブラウザ／動画／Windowsをミュートせず、非ゼロPCMが届くのに無音なら、キャプチャと元音抑止の両方を確認できます。PCMメーターだけでは元音抑止の証明になりません。

## 4. 安全な失敗

- 不正なURLや到達できないURLで、アプリを再起動せずYouTubeへ戻れること。
- アプリを2回起動しても、同じプロファイルを2つのプロセスが同時利用しないこと。
- 再起動すると通常再生へ戻ること。

- 通常再生時の音声
- PCM診断時のnon-zero増加とスピーカーの無音
- シーク・プレイリスト・動画遷移で起きた問題
